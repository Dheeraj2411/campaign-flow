1. High-Level System Architecture

CampaignFlow Pro is a modular monolith. All components run in a single
Laravel process namespace, sharing the same PostgreSQL 16 database, but
logically separated by service/domain boundaries. This avoids the
operational overhead of microservices while maintaining clear code
separation. PostgreSQL is used specifically for its jsonb GIN indexes
(contact tag filtering), timestampTz columns (timezone-aware message
history), and the @> containment operator for performant JSON queries.

3.2 Outbound Campaign Flow

Campaign Send

User clicks 'Send Campaign'

|

v

CampaignController@store

|- Validate quota (UsageService)

|- Verify WhatsApp token

|- Create Campaign (status=draft)

|- Dispatch DispatchCampaignJob

|

v

DispatchCampaignJob (medium queue)

|- Set campaign status = running

|- Query contacts (segment OR tag OR all)

|- Chunk(100) -> dispatch CampaignSendChunkJob x N

|- Bus::batch() — marks failed on any chunk exception

|

v

CampaignSendChunkJob x N (medium queue, parallel)

|- Personalize message per contact

|- Bulk-insert MessageLog rows (status=pending)

|- Dispatch SendMessageJob per log

|

v

SendMessageJob (high queue, per contact)

|- Redis RateLimiter (80/min per workspace)

|- Call WhatsAppService::sendTemplate()

|- Update MessageLog.status = sent / failed

|- On final failure: store failure_reason

3.3 Automation Trigger Flow

Automation Engine

Event occurs (e.g. 'message_received')

|

v

AutomationWorkflowService::executeTrigger(trigger, payload)

|- Fetch active workflows for workspace matching trigger

|- For each workflow:

|- conditionsMatch(conditions, payload) — exits if false

|- Create WorkflowExecution (status=running)

|- For each action:

|- performAction(workflow, payload, action)

|- 'send_campaign_message' -> SendMessageJob

|- 'tag_contact' -> contact.tags update

|- 'assign_conversation' -> Conversation.assigned_to

|- 'change_status' -> Conversation.status

|- 'delay' -> ResumeWorkflowJob::dispatch()->delay()

|- 'send_template' -> WhatsAppService::sendTemplate()

|- 'webhook' -> Http::post(url, payload)

|- Update WorkflowExecution (status=completed|failed)

5. Tag Manager UI Design

A slide-over panel (right drawer, 400px wide) accessible from the
Contacts page header. Built as Tags/Manager.vue.

  -------------------- --------------------------------------------------
  UI Element           Behavior

  Tag list             Workspace tags sorted alphabetically; each row
                       shows color swatch, name, contact count

  Create tag           Inline form at top: name input + color picker
                       (preset palette of 8 colors) + Save

  Rename tag           Click tag name to make it editable inline; blur or
                       Enter to save (PATCH /tags/{id})

  Delete tag           Trash icon → confirmation modal showing contact
                       count → DELETE /tags/{id}

  Tag contacts         In Contact detail: multi-select tag chips with
                       autocomplete; POST /contacts/{id}/tags
  -------------------- --------------------------------------------------
